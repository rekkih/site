# maimai KOP8th history

The qualifying-results section is automatic. Both official schedules close on 23 November 2026 at 23:59 JST, represented as the exclusive boundary `2026-11-24T00:00:00+09:00`. Before then, the section is hidden. After closing, it waits for an archived SEGA snapshot dated at or after that boundary, then displays the top two International or top seven Japan finishers, plus a separate Japan LCQ list for places 8–15. It uses the latest eligible snapshot, preserves SEGA's ordering for tied ranks, and waits if leading places are missing. These are qualifying positions from the feed, not confirmation that finalists completed registration or attended. No moderator action or additional API/storage is needed. Rules: https://maimai.sega.jp/kop8th/maimai/ and https://maimai.sega.com/kop8th/maimai_itr_en/.

Download visible scores from all saved snapshots as CSV from `/api/maimai/kop8th/csv`, also linked in the page's “About this history” section. The export includes both versions by default; `?server=ex` or `?server=m` limits it to one. Downloads only read saved history and never trigger collection. Each row includes the version, source update, collection time, rank, player name, score, sub-score, and record date. An empty cache returns 404; unavailable storage returns 503.

`/maimai/kop8th` defaults to International. `?server=ex` selects International and `?server=m` selects Japan Ver.; the API uses the same parameter at `/api/maimai/kop8th`.

The first visitor to a version collects its current SEGA feed. After that, the first visit after 02:00 JST (International) or 07:00 JST (Japan) checks again. If the source has not published the expected daily update, or a request fails, another visit can retry after 30 minutes. An open visible tab checks every 30 minutes and on returning to the tab. There is no scheduler, Worker, or historical backfill: days without visitors can be missed.

Configure the existing `CF_ACCOUNT_ID`, `CF_KV_NAMESPACE_ID`, and `CF_API_TOKEN` on the Next.js server. The token needs KV read/list/write access to that namespace. Production returns an unavailable response if KV is not configured. Development without KV uses process-local memory, surviving HMR but not restarts. No additional secrets are required.

New snapshots are stored without expiration under `maimai:kop8th:{international|japan}:snapshot:{sourceTimestampMilliseconds}:{sha256(archive)}`. Each value contains `collectedAt` and the complete original `payload`, including fields not used by the graph. Hashing the complete archive means concurrent collections with different contents write separate keys; writes to the same key contain the same value. Existing timestamp-only archive keys remain readable and are never migrated or rewritten. The `:check` key stores refresh timing/status separately. Archives are the source of truth; there is no mutable history index. Reads paginate and load at most six archive values concurrently, caching by full key so later-discovered variants are loaded too.

Cloudflare KV is eventually consistent. Simultaneous instances may collect different payloads for one timestamp; all competing archives remain stored. Public JSON, graph, and CSV select one snapshot per timestamp: an existing timestamp-only archive takes precedence, otherwise the earliest collection wins, with archive key ordering breaking equal-time ties. Readers converge as keys propagate, without duplicate graph entries. An already-loaded source timestamp is not collected again into history even if SEGA changes its contents later; its roster can still be refreshed. This is not a distributed exactly-once collector. Storage and upstream failures are logged with a `[maimai:version]` prefix and surfaced in the page without deleting history.

Player identity is exact display name within a server. Search alone normalizes full-width text. Renames start new histories; duplicate names in a snapshot are excluded from connected series and still displayed in the standings. Leaving the latest KOP roster can mean dropping below its top 100; it is not treated as a ban or deletion. These players retain all saved scores in the chart, JSON snapshots, and CSV, and appear as “Not currently ranked” with a “Last recorded” score in the table. Only current players receive current ranks or qualifying positions. Gaps remain for snapshots where they were absent. The JSON `currentPlayers` list separates current membership from preserved score history. Original archives are preserved. After moderator deletions, remaining players in each affected public snapshot are renumbered from 1 in their existing rank order, preserving source order for ties. Scores, DX scores, and source timestamps remain unchanged, so normal daily score differences remain and deletion creates no score update. Both source timestamp formats are interpreted as JST.

The latest roster is stored separately under `maimai:kop8th:{international|japan}:roster`, including source and collection timestamps. A new snapshot must be saved successfully before the roster is published; archive-write failure leaves the previous roster intact. Readers apply a roster only to an archive with the same source timestamp, so a roster that propagates first cannot hide players in older cached history. This detects removals even when KOP changes the roster without advancing its timestamp. Older feeds and failed/invalid responses cannot replace the latest confirmed roster within a collector. Existing installations fall back to the newest archive until the next scheduled successful collection. Collection still follows the visitor-triggered daily schedule above; removals are not detected instantly.

Moderators authenticated with the existing `canvas-mod-token` localStorage setting see a Delete button on each player row. Confirmation deletes all scores for that exact name in the selected version, including duplicate names. `DELETE /api/maimai/kop8th?server=ex|m` takes `{ "userName": "exact name" }` and requires the `x-mod-token` header, validated against `CANVAS_MOD_TOKEN`. Each deletion writes a separate permanent `maimai:kop8th:{international|japan}:deleted:{sha256(name)}` marker so concurrent deletions cannot overwrite one another and future imports cannot restore the player. This is a public visibility deletion; raw archives remain intact. There is no restore control. Filtering runs after cache reads for both JSON and CSV. If visibility storage is unreadable, those endpoints return 503. KV propagation can delay visibility changes on other instances; open tabs update on their next refresh.

Placement arrows and score differences compare exact player names against the latest snapshot from the previous JST calendar day. Missing days, new/renamed players, and duplicate names have no change indicator. The graph defaults to score and selects the top ten; the searchable table supports sorting, left-side selection markers, and horizontal scrolling on mobile.

The info icon above the player table lists moderator-removed names for the selected version, or states that nobody has been removed. It is available to all visitors on hover, keyboard focus, and tap. The JSON response exposes these exact names in `removedPlayers`, read from the persisted deletion markers; players who merely leave the KOP roster are not included. Moderator-removed scores remain excluded.
